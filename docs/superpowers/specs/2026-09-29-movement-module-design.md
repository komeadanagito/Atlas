# 运动模块双筛选设计规格

日期：2026-09-29  
状态：待用户审阅  
范围：Atlas「百宝箱」中的运动模块（现有模块 ID `fitness`）

## 目标

将百宝箱中的「健身」入口改名为「运动」，并把当前占位页替换成一个商城式的双层筛选界面。用户先选训练类型，再选与该类型相关的器械或动作方式。此阶段只实现分类浏览与筛选控件；不提供训练动作、器械商品、记录、统计、搜索或数据库内容。

## 分类依据

ACSM（美国运动医学会）的运动处方指导将心肺训练、抗阻训练、柔韧训练和神经运动训练作为主要训练组成部分（[Garber et al., 2011, PubMed](https://pubmed.ncbi.nlm.nih.gov/21694556/)）。分类层级据此分开「训练目标／类型」和「训练载体／动作方式」，避免把有氧／力量和器械／动作放进同一个分类维度。

### 顶部：训练类型

- 全部运动
- 有氧心肺
- 力量／抗阻（无氧）
- 柔韧／活动度
- 平衡／协调（神经运动）

### 左侧：依顶部类型动态切换的子类

每个顶部类型下的左侧列表都以「全部方式」开头；后续选项为：

- 全部运动：有氧器械、户外／团体有氧、固定器械、自由重量、自重训练、弹力带／小工具、拉伸／活动度、平衡／协调。
- 有氧心肺：有氧器械、跑步／户外、骑行、划船／水上、团体有氧。
- 力量／抗阻：固定器械、自由重量、自重训练、弹力带／小工具。
- 柔韧／活动度：动态拉伸、静态拉伸、瑜伽、普拉提、泡沫轴／放松。
- 平衡／协调：平衡训练、核心稳定、敏捷／协调、本体感觉。

子类是筛选项标签，不展示举例、图卡、商品、动作说明或伪造的数量。后续若需调整分类，可在添加真实目录内容前单独校准。

## 页面结构与视觉

沿用 Atlas 当前浅色界面、Inter 字体、白色表面、细灰色边线及运动模块青绿色强调色，不改变全局设计系统。页面保留「返回百宝箱」与「运动」标题；顶部横向展示训练类型，下面采用两栏目录结构：左侧为子类筛选，右侧作为未来目录承载区。右侧在此版本中保持空白，不用示例卡片或虚构空数据填充。

桌面端保持顶部分类＋左侧窄筛选栏＋右侧留白的商城目录骨架；移动端将顶部分类和子类都改为可横向浏览的选项条，保证页面宽度不溢出且主视角不被筛选内容挤乱。选中态以青绿色文字／轻底色或边线、明确选中标记表达；默认、悬停、键盘焦点和按下状态沿用现有 tokens。

## 交互与状态

- 初始选择「全部运动」和「全部方式」。
- 顶部分类可单选；更换顶部分类时，子类选择重置为该分类的「全部方式」，并立即更新左侧子类。
- 左侧子类可单选，使用 `aria-pressed` 暴露选中状态。两个筛选器均由原生按钮组成，支持键盘焦点与激活。
- 不添加未实现的筛选结果、数量、搜索框、重置按钮或假交互；右侧内容区始终空白。
- 小幅、快速的交互反馈，不增加复杂动画，并尊重 `prefers-reduced-motion`。

## 实现边界

新增独立运动筛选页面组件与本地静态分类配置；`fitness` 作为内部模块 ID 保持不变，避免破坏路由和主题绑定，只调整用户可见名称。其他百宝箱模块继续使用现有占位页面。分类状态只存在于当前组件内，不持久化、不发网络请求，不改 API、数据库或核心时间轴。

## 验收标准

1. 百宝箱入口显示「运动」，点击后进入新的双筛选页，返回按钮仍能回到百宝箱。
2. 顶部选择有且只有一个当前训练类型，且有氧、抗阻、柔韧、神经运动分类彼此区分。
3. 左侧子类随训练类型切换；切换顶部时旧子类不会残留为错误选中状态。
4. 结果区域没有器械或动作内容、卡片、示例数据或数量。
5. 桌面端为顶部＋左侧结构；窄屏两层筛选均可触控横向选择，无横向页面溢出。
6. 键盘和辅助技术能够识别筛选组及其选择状态；新增交互使用现有主题 tokens。
7. 新增组件测试覆盖默认选择、顶部切换及子类重置；现有 Web 与 API 测试保持通过。
